# 기획서: mock-board (React)

## 1. 개요

로그인한 회원이 게시판과 회원 정보를 관리하는 웹 앱이다.
아직 서버가 없으므로 모든 데이터는 **mock 데이터**를 사용한다.
단, 화면 코드는 **실제 서버와 통신하는 것과 같은 형태**로 작성한다.

- 화면은 항상 **axios**로 REST API를 호출한다.
- axios에 **mock adapter**를 붙여서 요청을 가짜 서버가 받아 응답한다.
- 나중에 실제 서버가 생기면 mock adapter만 끄고 `baseURL`을 바꾸면 된다. 화면과 서비스 코드는 고치지 않는다.

## 2. 기술 스택

`react-apps/CLAUDE 복사본.md` 가이드를 따른다.

| 항목 | 내용 |
|---|---|
| 빌드 도구 | Vite (`npm create vite@latest my-app05 -- --template react`) |
| 언어 | React 19 + JavaScript (TypeScript 사용 안 함) |
| CSS | Tailwind CSS v4 (`tailwindcss`, `@tailwindcss/vite`) |
| 통신 | axios |
| Mock 서버 | axios-mock-adapter (응답 지연 300ms로 실제 통신처럼 보이게 함) |
| 라우팅 | react-router-dom |
| 상태 관리 | Zustand (로그인 정보) |
| 린트 | oxlint (`no-unused-vars` 끔) |
| 개발 서버 | 포트 3000, 시작 시 브라우저 자동 열림 |

## 3. 기능

### 3.1 로그인

- 아이디와 비밀번호를 입력해 로그인한다.
- 성공하면 서버가 **토큰**과 **회원 정보**를 돌려준다. 토큰은 이후 모든 요청의 `Authorization` 헤더에 담는다.
- 실패하면 "아이디 또는 비밀번호가 올바르지 않습니다." 메시지를 보여준다.
- 로그인 정보는 브라우저에 저장해 새로고침해도 유지한다.
- **로그인 없이** 게시글 목록·상세는 볼 수 있다.
- 로그인이 필요한 화면(게시글 등록·수정, 회원정보)에 들어가면 로그인 화면으로 보내고, 로그인하면 원래 가려던 화면으로 돌아간다.
- 상단 바에서 로그인·로그아웃할 수 있다.

### 3.2 메뉴

상단 바에 메뉴 두 개가 보인다. **첫 화면(`/`)은 게시글 목록**이다.

| 메뉴 | 경로 |
|---|---|
| 게시판 | `/board` |
| 회원정보 | `/members` (로그인 필요) |

상단 바 오른쪽에는 로그인했으면 회원의 이름, 권한, 로그아웃 버튼을, 로그인하지 않았으면 로그인 버튼을 보여준다.

### 3.3 게시판

| 기능 | 내용 |
|---|---|
| 목록 | 번호, 제목, 글쓴이, 조회수, 등록일을 표로 보여준다. 최신 글이 위에 온다. |
| 상세 | 제목, 내용, 글쓴이, 조회수, 등록일, 수정일을 보여준다. 상세에 들어갈 때마다 조회수가 1 오른다. |
| 등록 | 제목, 내용을 입력한다. 글쓴이는 로그인한 회원으로 자동 지정된다. |
| 수정 | 제목, 내용을 고친다. 수정일이 갱신된다. |
| 삭제 | 확인 창을 띄운 뒤 삭제한다. |

게시글 데이터:

| 필드 | 설명 |
|---|---|
| id | 글 번호 |
| title | 제목 |
| content | 내용 |
| authorId / authorName | 글쓴이 |
| views | 조회수 |
| createdAt | 등록일 |
| updatedAt | 수정일 |

권한:

| 기능 | 비로그인 | 사용자 | 운영자 |
|---|---|---|---|
| 목록·상세 보기 | O | O | O |
| 등록 | X (로그인 화면으로) | O | O |
| 수정 | X | **본인 글만** | 모든 글 |
| 삭제 | X | **본인 글만** | 모든 글 |

- 다른 사람의 글은 보기만 가능하다. 수정·삭제 버튼을 보여주지 않는다.
- 수정 화면 주소로 직접 들어와도 권한이 없으면 상세 화면으로 돌려보낸다.
- 서버(mock)도 토큰이 없으면 401, 다른 사람의 글을 고치거나 지우려 하면 403으로 거절한다.

#### 3.3.0 비공개 글

- 글쓰기 화면의 **등록 버튼 바로 위**에 "🔒 비공개로 올리기" 체크 칸을 둔다. 수정 화면에서도 바꿀 수 있다.
- 비공개 글은 **운영자**와 **글쓴이 본인**만 볼 수 있다. (본인도 못 보면 수정·삭제를 할 수 없으므로 본인은 볼 수 있게 한다)
- 다른 회원과 비로그인 방문자의 게시글 목록에는 나오지 않는다. 주소로 직접 들어오면 "비공개 글입니다." 안내를 보여준다.
- 볼 수 있는 사람에게는 목록과 상세에 🔒 비공개 표시를 보여준다.
- 비공개 글의 댓글·추천도 볼 수 있는 사람만 쓰고 볼 수 있다.

게시글 데이터에 `isPrivate`(비공개 여부)를 추가한다.

#### 3.3.1 댓글

게시글 상세 화면 아래에 댓글을 보여주고 남길 수 있다.

| 기능 | 비로그인 | 사용자 | 운영자 |
|---|---|---|---|
| 댓글 보기 | O | O | O |
| 댓글 등록 | X (로그인 안내) | O | O |
| 댓글 수정 | X | **본인 댓글만** | **본인 댓글만** |
| 댓글 삭제 | X | **본인 댓글만** | **모든 댓글** |

- 댓글은 오래된 순서로 보여준다. 글쓴이, 내용, 등록일을 보여주고, 수정한 댓글에는 "(수정됨)"을 붙인다.
- 수정은 그 자리에서 입력칸으로 바뀌어 고친다.
- 게시글 목록의 제목 옆에 댓글 수를 보여준다.
- 게시글을 삭제하면 그 글의 댓글도 함께 삭제한다.

댓글 데이터:

| 필드 | 설명 |
|---|---|
| id | 댓글 번호 |
| postId | 게시글 번호 |
| content | 내용 |
| authorId / authorName | 글쓴이 |
| votes | 회원별 추천·비추천 |
| createdAt | 등록일 |
| updatedAt | 수정일 |

#### 3.3.2 추천·비추천

- 로그인한 회원은 **다른 사람의 게시글과 댓글**에 👍 추천 또는 👎 비추천을 누를 수 있다. 본인 글·댓글에는 누를 수 없다.
- 글(댓글) 하나에 한 번만 표시할 수 있다. 같은 버튼을 다시 누르면 취소되고, 반대 버튼을 누르면 바뀐다.
- 내가 누른 버튼은 색으로 표시한다.
- 로그인하지 않고 누르면 로그인 화면으로 보낸다.
- 게시글 목록에 추천 수를 보여준다.

게시글·댓글 데이터에 `votes`(회원별 추천/비추천)를 추가한다. 댓글 응답에도 `likes`, `dislikes`, `myVote`를 담는다.

게시글 응답에는 `likes`(추천 수), `dislikes`(비추천 수), `myVote`(내가 누른 것: `up` / `down` / 없음), `commentCount`(댓글 수)를 담아 돌려준다.

### 3.4 회원정보

| 기능 | 운영자 | 사용자 |
|---|---|---|
| 회원 목록 보기 | O | O |
| 회원 등록 | O | X |
| 회원 수정 | O | X |
| 회원 삭제 | O | X |

- 회원 등록 시 권한을 **운영자(ADMIN)** 또는 **사용자(USER)** 중에서 고른다.
- 사용자는 회원 목록을 **읽기만** 가능하다. 등록·수정·삭제 버튼을 보여주지 않고, 서버(mock)도 요청을 403으로 거절한다.
- 등록·수정·삭제는 운영자(관리자)만 할 수 있다.
- 아이디는 중복될 수 없다.
- 운영자는 자기 자신을 삭제할 수 없다.
- 수정할 때 비밀번호를 비워 두면 기존 비밀번호를 유지한다.

회원 데이터:

| 필드 | 설명 |
|---|---|
| id | 회원 번호 |
| username | 아이디 |
| password | 비밀번호 (응답에는 포함하지 않음) |
| name | 이름 |
| role | `ADMIN`(운영자) / `USER`(사용자) |
| createdAt | 가입일 |

### 3.5 디자인

**하늘·구름** 테마로, 아기자기하고 귀여운 분위기를 유지한다. 아이콘 라이브러리는 쓰지 않고 이모지로 장식한다.

| 항목 | 내용 |
|---|---|
| 색 | 하늘색(포인트), 흰 구름, 노란 햇살 포인트, 남색 글자. 민트·라벤더는 보조 색 |
| 배경 | 위는 하늘색, 아래로 갈수록 하얗게 + 작은 구름 점 무늬 |
| 글꼴 | 제목 `Jua`, 본문 `Gowun Dodum` (Google Fonts) |
| 모양 | 둥근 카드·알약 모양 버튼, 점선 구분선 |
| 공통 스타일 | `src/index.css`에 `card`, `btn`, `input`, `badge`, `table-cute` 등으로 모아 둔다 |
| 권한 표시 | 운영자 👑 / 사용자 🐣 |

#### 테마 선택

상단 바 오른쪽(로그인 화면은 오른쪽 위)의 테마 버튼으로 4가지 테마 중 하나를 고른다. 고른 테마는 브라우저에 저장해 새로고침해도 유지한다. 기본은 하늘이다.

| 테마 | 버튼 | 분위기 | 하트 |
|---|---|---|---|
| 하늘 (기본) | ☁️ | 하늘색 + 흰 구름 + 노란 햇살 | 💙 |
| 핑크 | 🐰 | 파스텔 핑크 + 민트 + 땡땡이 | 💗 |
| 숲 | 🐿️ | 연두 + 베이지 + 숲속 장식 🍀🌼🍄 | 💚 |
| 밤하늘 | 🌙 | 남색 배경(다크) + 노란 별빛 ⭐✨🪐 | 💛 |

- 색: `src/index.css`의 `:root[data-theme="..."]` 블록에서 테마별 값을 덮어쓴다.
- 장식(마스코트, 하트, 불러오는 중 문구, 로그인 화면 장식): `src/utils/themes.js`
- 선택 상태: `src/stores/themeStore.js` → `<html data-theme>`에 반영

색은 이름이 아니라 **역할 이름**(`point`, `soft`, `line`, `ink`, `sun` 등)으로 쓴다. 모든 색 값은 `src/index.css`의 `@theme`에만 있으므로, 테마를 바꿀 때는 그 값만 고치면 된다.

로그인 화면:
- 왼쪽에 앱 소개 문구와 구름 캐릭터, 오른쪽에 로그인 카드를 둔다. (좁은 화면에서는 위아래로 쌓인다)
- 하늘색 그라데이션 배경 위에 ☁️☀️🎈🌈 장식이 둥실둥실 떠다닌다.

## 4. API 명세 (mock)

모든 요청은 `/api`로 시작한다. 권한이 "로그인" 이상인 요청은 토큰이 없으면 401, 권한이 모자라면 403을 돌려준다.

| 메서드 | 경로 | 설명 | 권한 |
|---|---|---|---|
| POST | `/api/auth/login` | 로그인 → `{ token, user }` | 누구나 |
| GET | `/api/posts` | 게시글 목록 (볼 수 없는 비공개 글 제외) | 누구나 |
| GET | `/api/posts/:id` | 게시글 상세 (조회수 +1, 비공개 글은 운영자·본인만) | 누구나 |
| POST | `/api/posts` | 게시글 등록 | 로그인 |
| PUT | `/api/posts/:id` | 게시글 수정 | 본인 / 운영자 |
| DELETE | `/api/posts/:id` | 게시글 삭제 | 본인 / 운영자 |
| POST | `/api/posts/:id/vote` | 추천·비추천 `{ type: 'up' \| 'down' }` (같은 값이면 취소) | 로그인 (본인 글 제외) |
| GET | `/api/posts/:id/comments` | 댓글 목록 | 누구나 |
| POST | `/api/posts/:id/comments` | 댓글 등록 | 로그인 |
| PUT | `/api/comments/:id` | 댓글 수정 | 본인 |
| DELETE | `/api/comments/:id` | 댓글 삭제 | 본인 / 운영자 |
| POST | `/api/comments/:id/vote` | 댓글 추천·비추천 `{ type: 'up' \| 'down' }` (같은 값이면 취소) | 로그인 (본인 댓글 제외) |
| GET | `/api/members` | 회원 목록 | 로그인 |
| GET | `/api/members/:id` | 회원 상세 | 로그인 |
| POST | `/api/members` | 회원 등록 | 운영자 |
| PUT | `/api/members/:id` | 회원 수정 | 운영자 |
| DELETE | `/api/members/:id` | 회원 삭제 | 운영자 |

오류 응답은 `{ message }` 형태로 돌려주고, 화면은 이 메시지를 그대로 보여준다.

mock 데이터는 **axios-mock-adapter가 메모리에 들고 있다** (`src/utils/mock/db.js`). 앱을 쓰는 동안에는 등록·수정·삭제한 내용이 유지되고, 새로고침하면 초기 데이터로 돌아간다.
